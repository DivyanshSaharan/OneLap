# Mission-first interface

Deployment UI follow-up: the mission JSON importer is removed from the workspace, with no route or hidden toggle to restore it. Users create outings through the normal model flow. Existing saved/imported missions remain readable with their original provenance labels; no local content is deleted. Import parsing/component utilities remain for isolated developer tests, not the shipped UI. Regression checks assert the importer is absent both online and offline.

The later sign-in polish moves account controls into the header and replaces the explanatory login card with a responsive welcome layout. A dismissible header chooser keeps the official nonce-bound Google button. Technical session/Atlas explanations are removed from the main screen; plain-language privacy details sit behind a footer disclosure. Loading, generation, pocket and journal copy focuses on the user's next action. Explicit upload and model-sharing consent remain unchanged. Mandatory sign-in and account isolation are not relaxed.

Polish verification: 239 frontend tests and seven synthetic Edge browser checks pass, including header placement, chooser dismissal/stale callbacks, 320/390/1280px layouts, account isolation and locked offline reload. Production build passes; desktop and phone-width sign-in screenshots were inspected. No hosted calls, account creation or journal uploads were made. The owner approved committing and pushing this cleanup, including removal of the importer, before Docker preparation.

The initial screen shows preparation and the mission/pocket experience, not an empty journal or a developer checklist. Returning with a mission or existing notes reveals the journal. Cloud sync/privacy and the next-outing model controls are separate collapsed sections; opening them alone makes no request. Saving a note stays local, sync consent stays per operation, and AI follow-up keeps its separate reviewed-data consent.

Provenance remains expandable, but the captured-file utility is no longer present in the deployment UI. Mandatory Google sign-in gates the entire workspace: mission preparation, saved missions and journals are not mounted until identity is verified. Unknown identity or unavailable authentication does not expose a legacy connection panel. Logout immediately returns to the sign-in screen, including when remote revocation is unconfirmed. An already signed-in open tab works offline; reopening requires online session verification.

Verification on October 11: 200 frontend unit tests; six Edge production-browser checks; TypeScript and production build; the seven-stage packaged-server fixture workflow with verified cleanup; 24 public-file/handoff and nine request-boundary tests. Responsive preparation and collapsed journal screenshots were inspected. Checks use disposable profiles and fictional data, not the user's personal journal or physical phone. No paid requests are made by this UI increment.
